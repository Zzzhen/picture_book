# 书芽芽书架资料编辑与批量管理设计规格

日期：2026-08-05  
状态：已完成交互确认，待用户审阅规格文档  
范围：家庭数字绘本馆 V1-Core

## 1. 目标

将“修改书架资料”“向书架添加绘本”“管理书架内已有绘本”拆成三个职责清晰的流程：

1. 编辑书架只修改名称和说明。
2. 添加绘本使用独立页面，不再借用编辑页面。
3. 书架详情页提供选择模式，用于批量移出和书架内置顶。

置顶只改变绘本在当前书架内的展示顺序，不改变绘本馆首页顺序，也不影响同一本绘本在其他书架中的顺序。

## 2. 非目标

- 不实现绘本馆首页置顶。
- 不实现跨书架移动或复制。
- 不实现拖拽排序。
- 不实现分享运营版能力。
- 不新增数据库集合。
- 不要求新增数据库索引。

## 3. 当前实现存在的问题

- `pages/bookshelf-edit/index` 同时承担资料编辑和绘本关系编辑，职责混杂。
- `pages/bookshelf-detail/index` 仅加载前 50 本，无法覆盖最多 500 本的书架。
- 书架详情没有批量选择状态，无法直接移出或置顶。
- “添加绘本”依赖编辑页；移除编辑页选书后需要独立入口承接。
- 已有 `bookshelf_books.sort_order` 是书架级排序字段，但前端尚未提供置顶交互。

## 4. 信息架构与路由

### 4.1 书架详情

路由：`pages/bookshelf-detail/index`

职责：

- 展示书架名称、说明、绘本数量和书籍网格。
- 进入资料编辑页。
- 进入选择模式并执行移出、置顶。
- 进入独立添加绘本页。

### 4.2 编辑书架资料

路由：`pages/bookshelf-edit/index`

职责：

- 新建书架时填写名称、说明。
- 编辑已有书架时只修改名称、说明。
- 删除已有书架。

该页面不得加载馆藏列表，不得修改 `bookshelf_books` 关系。

### 4.3 添加绘本到书架

新增路由：`pages/bookshelf-book-picker/index`

职责：

- 展示绘本馆中尚未加入当前书架的藏书。
- 支持搜索、多选、全选当前加载的候选书籍、取消和确认加入。
- 不提供移出、置顶或书架资料编辑能力。

## 5. 书架详情交互设计

### 5.1 普通状态

- 页面顶部沿用 `app-header`，不向 Header 传编辑状态或操作插槽。
- 书架信息区右上角显示两个文字按钮：`编辑`、`选择`。
- `编辑`跳转到 `pages/bookshelf-edit/index?id=<bookshelf_id>`。
- `选择`仅在书架内至少有一本绘本时显示。
- `＋ 添加绘本`和空状态主按钮跳转到 `pages/bookshelf-book-picker/index?id=<bookshelf_id>`。
- 点击普通状态下的绘本进入绘本详情。

### 5.2 选择状态

进入选择状态后：

- 隐藏普通书架信息区和“添加绘本”按钮。
- 顶部选择栏左侧为`全选`或`取消全选`。
- 中间主标题为`选择书籍`。
- 中间副标题为`已选择 N 本书籍`。
- 右侧为`取消`，点击后清空选择并返回普通状态。
- 点击绘本只切换选中状态，不进入绘本详情。
- 选中态同时使用品牌绿色描边、轻遮罩和圆形勾选标记，不能只依赖颜色表达。
- 底部固定操作栏显示`移出书架`和`置顶`。
- 未选择任何绘本时，两个操作按钮均禁用。
- 底部栏适配 `env(safe-area-inset-bottom)`，书籍网格预留等量底部空间。

### 5.3 全选

- 详情页进入可操作状态前，按游标加载整个书架，单页 50 本，最多 500 本。
- `全选`选择当前书架已加载的全部书籍，而不是仅选择首屏可见书籍。
- 已全选时按钮文案变为`取消全选`。
- 数据重新加载后清空旧选择，避免对已不存在的关系执行操作。

### 5.4 移出书架

- 点击`移出书架`显示二次确认弹窗。
- 标题：`移出所选书籍？`
- 说明：`只会从当前书架移除，不会删除绘本馆里的藏书。`
- 确认后按每批不超过 50 个 ID 调用现有 `removeBooks`。
- 操作期间禁用重复点击并显示加载状态。
- 全部成功后退出选择状态、重新加载书架并显示成功提示。
- 任一批失败时停止后续批次，重新加载服务端真实数据并提示用户重试。

### 5.5 置顶

- 点击`置顶`后，所选绘本保持其操作前的相对顺序，一起移动到当前书架最前方。
- 置顶完成后退出选择状态并重新加载书架。
- 不显示永久“已置顶”角标；再次选择其他绘本置顶时，新的选择移动到更前方。
- 置顶只更新 `bookshelf_books.sort_order`，不得更新 `user_books.custom_sort`。

## 6. 编辑书架交互设计

- 保留书架名称和说明输入框。
- 名称沿用现有必填及长度校验。
- 说明沿用现有可选及长度校验。
- 保存和删除按钮固定在页面底部并适配安全区。
- 新建状态不显示删除按钮。
- 编辑状态保留删除书架二次确认。
- 删除当前页面中的馆藏加载、搜索、全选、绘本列表、关系差异计算、`addBooks`和`removeBooks`调用。
- 保存已有书架只调用 `updateShelf`；新建只调用 `createShelf`。

## 7. 添加绘本页交互设计

- 顶部标题为`添加绘本`并显示返回按钮。
- 页面说明明确当前目标书架名称。
- 搜索范围是用户绘本馆中的已有藏书，不触发 ISBN 付费回源。
- 当前书架已有绘本从候选数据中排除，避免重复选择。
- 候选绘本使用与书架详情一致的三列封面网格。
- 支持逐本选择和全选当前已加载候选数据。
- 顶部显示`已选择 N 本`。
- 底部固定主按钮文案为`加入书架（N）`，N 为 0 时禁用。
- 确认加入时按每批不超过 50 个 ID 调用现有 `addBooks`。
- 成功后返回书架详情，由详情页 `onShow` 重新加载。
- 没有候选绘本时显示：`绘本馆里的藏书都已加入这个书架`。
- 搜索无结果时显示独立搜索空状态，不与全局空状态混用。

## 8. 页面状态模型

书架详情增加以下数据状态：

- `state`: `loading | content | empty | error`
- `mode`: `normal | selecting`
- `selectedIds`: 选中的 `user_book_id` 集合在视图层的数组表达
- `allSelected`: 当前是否已选择全部书架书籍
- `operating`: `"" | removing | pinning`
- `removeConfirmVisible`: 是否显示移出确认弹窗

添加绘本页包含：

- `state`: `loading | content | empty | search-empty | error`
- `keyword`
- `books`
- `displayBooks`
- `selectedIds`
- `allSelected`
- `saving`

## 9. 组件策略

- 扩展现有 `book-card`，增加可选的 `selectable`、`selected` 属性，默认值均为 `false`。
- 默认属性下的现有绘本馆、书架页面行为和视觉不得变化。
- `selectable=true` 时显示选择标记容器。
- 页面负责决定点击是打开详情还是切换选择；组件只发出统一点击事件。
- 继续复用 `confirm-dialog`、`empty-state`、`search-field`和`ui-button`。
- 不在页面内复制一套新的弹窗或按钮视觉系统。

## 10. 云函数契约

在 `bookshelfService` 新增：

### `pinBooks`

请求：

```json
{
  "action": "pinBooks",
  "payload": {
    "bookshelf_id": "书架 ID",
    "user_book_ids": ["馆藏绘本 ID"]
  },
  "requestId": "UUID"
}
```

成功响应数据：

```json
{
  "updated_count": 2
}
```

规则：

- `user_book_ids` 必须去重，数量为 1–500。
- 服务端验证书架存在、归属当前用户且未删除。
- 服务端验证每个 ID 都存在于当前书架；发现非法关系时整体拒绝开始执行。
- 读取当前书架全部关系并按 `sort_order ASC, _id ASC` 得到稳定顺序。
- 所选关系按当前稳定顺序排列，不信任客户端传入顺序。
- 取当前最小 `sort_order`，为所选关系分配连续且更小的值，使其整体移动到最前。
- 当新值接近允许下界时，先将当前书架全部关系归一化为 `0..N-1`，再执行置顶。
- 写入按安全批次执行；接口保持请求幂等保护。
- 返回实际更新数量。

错误码沿用：

- `INVALID_ARGUMENT`
- `BOOKSHELF_NOT_FOUND`
- `FORBIDDEN`
- `RELATION_NOT_FOUND`
- `DATABASE_ERROR`

`cloudfunctions/_shared/contracts.js` 和服务契约测试必须同步增加 `pinBooks`。
主开发文档第 15 节的 `bookshelfService` action 清单和请求示例也必须同步更新，避免文档与代码契约分叉。

## 11. 数据模型与排序隔离

继续使用现有关系集合：

```text
bookshelf_books
  owner_id
  bookshelf_id
  user_book_id
  sort_order
  created_at
```

隔离关系：

- `bookshelf_books.sort_order`：某一本藏书在某一个书架中的顺序。
- `user_books.custom_sort`：藏书在绘本馆首页中的自定义顺序。

`pinBooks`只能更新前者。现有 `shelf_order` 复合索引已经覆盖查询，不新增索引。

## 12. 分页与批量边界

- `listShelfBooks` 单次仍限制最多 50 本。
- 详情页通过 `next_cursor` 连续加载，最多累计 500 本。
- 添加、移出调用按 50 个 ID 分批。
- `pinBooks`允许一次表达最多 500 本，由服务端负责安全写入批次。
- 页面不得使用固定的首批数据计算“全选”或数量。
- 所有 ID 数组在发送前去重。

## 13. 安全与一致性

- 所有云函数资源操作继续使用服务端用户身份，不接受客户端 owner ID。
- 所有书架和关系均检查所有权。
- 未选择数据时前端禁用操作，服务端仍独立验证非空数组。
- 操作按钮使用 `operating/saving` 锁避免重复提交。
- 批处理发生部分成功后，客户端不在本地猜测最终结果，而是重新加载服务端数据。
- 删除书架和移出绘本是不同操作；文案必须清晰区分。

## 14. 视觉规范

- 延续书芽芽的米白纸张背景、森林绿主色和低饱和砖红危险色。
- 维持三列统一比例封面，不因原图尺寸改变卡片高度。
- 选中描边清晰但克制，避免大面积高饱和遮罩。
- 选择计数是主要状态信息，字号层级高于普通数量说明。
- 底部批量操作栏使用实底表面和轻微顶部阴影，与内容区分离。
- 所有按钮文字使用真实业务文案，不使用图标代替关键动作。

## 15. 错误与空状态

- 详情加载失败：提供错误说明和重试入口。
- 书架被删除或无权访问：提示后返回书架列表。
- 移出失败：重新加载并提示`部分操作可能未完成，请重试`。
- 置顶失败：重新加载并提示`置顶失败，请重试`。
- 添加失败：保留页面选择状态，重新同步当前书架关系后提示重试。
- 添加页全局空状态与搜索空状态必须分别呈现。

## 16. 测试与验收标准

### 16.1 前端行为

- 普通状态存在`编辑`和`选择`，空书架隐藏`选择`。
- 编辑跳转到资料编辑页，添加跳转到独立选择页。
- 进入选择状态后隐藏添加入口。
- 点击书籍能够选中、取消，并正确更新计数。
- 全选与取消全选覆盖全部 500 本加载数据。
- 0 本选中时底部操作禁用。
- 普通状态点击书籍仍进入详情。
- 编辑页源码不再出现馆藏列表加载或关系增删调用。

### 16.2 服务契约

- `pinBooks`加入严格 action 白名单。
- 拒绝未知字段、空 ID、重复 ID、超过 500 个 ID。
- 拒绝越权书架和不属于该书架的绘本关系。

### 16.3 排序

- 单本置顶移动到第一位。
- 多本置顶保持原相对顺序。
- 已在最前的绘本再次置顶结果稳定。
- 置顶不修改 `user_books.custom_sort`。
- 置顶一个书架不改变其他书架内顺序。
- 接近排序下界时执行归一化后仍保持原顺序。

### 16.4 批量操作

- 51、100、500 本移出能够按批处理。
- 51、100、500 本置顶能够完成并保持顺序。
- 中途失败后页面重新加载真实数据，按钮恢复可用。

### 16.5 视觉与布局

- 320、375、430px 宽度下三列封面、选择标记和底部栏无溢出。
- 底部栏不被小程序安全区或系统手势区域遮挡。
- 选择标记在浅色和深色封面上均清楚可见。
- 长书名、省略文本和 500 本计数不会挤压顶部操作。

## 17. 发布影响

- 需要重新上传并部署 `bookshelfService` 云函数。
- 需要重新编译并上传小程序前端。
- 需要在 `app.json` 和 `sitemap.json` 注册新增页面，并同步开发文档中的正式路由清单。
- 不需要创建新集合。
- 不需要配置新数据库索引。
- 不需要增加环境变量。
