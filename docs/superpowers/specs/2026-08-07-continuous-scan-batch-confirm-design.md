# 连续扫码待确认列表与批量入馆设计规格

日期：2026-08-07  
状态：交互设计已确认，待用户审阅规格文档  
范围：家庭数字绘本馆 V1-Core，`pages/add-book/index`

## 1. 目标

重构连续扫码为“自动扫描收集 → 当前页核对 → 统一入馆 → 可选加入一个书架”的流程。

- 扫码成功后自动继续下一本，不要求用户反复点击继续。
- 扫码阶段只收集标准图书信息，不写入绘本馆。
- 用户结束扫码后在当前页面查看、合并和删除待确认书籍。
- 用户点击确认后逐册写入绘本馆。
- 用户可以选择一个目标书架；未选择时不修改任何书架关系。
- 移除独立汇总页面和“结束并查看汇总”入口。

## 2. 非目标

- 不实现自定义相机扫码组件，继续使用微信 `wx.scanCode`。
- 不支持一次选择多个目标书架。
- 不新增连续扫码云数据库集合。
- 不把全部 ISBN 查询或入馆操作封装成一个云函数批量请求。
- 不修改单次扫码、ISBN 手工输入、缓存书库搜索和手工录入流程。

## 3. 已确认的产品规则

1. 点击“开始扫码”后进入自动循环。
2. 每次成功识别并查到图书后显示约 800 毫秒成功反馈，再自动调起下一次 `wx.scanCode`。
3. 扫码阶段不调用 `libraryService.addBook`。
4. 同一 ISBN 在本轮列表中合并为一行，并累计本轮册数。
5. 系统扫码界面取消或返回，等同结束自动扫描，返回当前页面展示列表。
6. 成功或重复扫描自动继续；查询失败暂停循环。
7. 失败时提供重试、手工录入、跳过并继续和结束扫码。
8. 待确认记录可删除，删除不需要服务端补偿，因为尚未入馆。
9. 结束后可以重新点击“开始扫码”，继续当前会话并保留已有列表。
10. 确认入馆时可选一个书架，也可以不选择。
11. 未选择书架时只入馆；不执行任何书架 action。
12. 用户未确认就离开页面时不入馆，本地草稿保留 24 小时。

## 4. 微信原生扫码约束

`wx.scanCode` 每次只能返回一个条码，并会打开微信系统扫码界面。系统界面打开期间，小程序页面按钮不可点击。因此：

- 成功回调返回小程序页面后进入 800 毫秒反馈窗口。
- 反馈窗口中显示“扫码成功，即将继续扫描”和“结束扫码”。
- 倒计时结束且会话仍为自动扫描状态时，再次调用 `wx.scanCode`。
- 用户在系统扫码界面取消，立即停止自动循环并展示当前列表。
- 页面维护单一循环锁，禁止计时器和用户点击造成重叠扫码。

## 5. 页面状态

### 5.1 页面模式

连续扫码继续使用 `mode === "continuous"`，删除 `mode === "summary"`。

在连续扫码模式内增加：

```text
continuousPhase:
  "ready"       未开始或已结束，可开始扫码
  "opening"     正在调用系统扫码
  "looking_up"  正在查询 ISBN
  "success"     成功反馈倒计时
  "paused"      查询失败，等待用户处理
  "submitting"  正在统一入馆或加入书架
  "completed"   全部完成，即将返回绘本馆
```

### 5.2 会话数据

```text
session:
  total          系统扫码成功或非取消失败的尝试数
  successful     成功识别并进入待确认列表的扫描次数
  skipped        用户跳过的失败次数
  failures       查询或识别失败次数

scanItems[]:
  isbn13
  edition_id
  title
  contributors_text
  publisher
  cover_file_id
  scan_count       本轮扫到的册数
  committed_count  已成功写入绘本馆的册数
  commit_operations 每册一个稳定 requestId 及提交状态
  user_book_id
  status           pending | submitting | added | failed
  error_message
  cache_hit
  provider_called
```

同一 `edition_id` 或 ISBN 只能有一条 `scanItems`。再次扫码时增加 `scan_count`，不创建重复行。

## 6. 扫码流程

### 6.1 开始

- 初始按钮文案为“开始扫码”。
- 点击后设置自动循环标志并调用 `scanContinuous`。
- 已存在 24 小时内草稿时继续原会话，不清空列表。
- 达到 100 次扫描上限后停止循环并回到列表，不跳转页面。

### 6.2 成功

1. `wx.scanCode` 返回条码。
2. 标准化并校验 ISBN。
3. 调用 `bookService.lookupByIsbn`；遇到 `BOOK_LOOKUP_IN_PROGRESS` 沿用现有轮询。
4. 将标准版本信息合并进 `scanItems`。
5. `session.successful` 增加 1。
6. 立即持久化本地会话。
7. 显示“扫码成功”以及书名，进入 800 毫秒反馈窗口。
8. 倒计时结束后检查循环标志、页面存活状态和 100 次上限，再开启下一次扫描。

成功阶段不得调用 `libraryService.listBooks`、`addBook` 或 `updateBook`。

### 6.3 失败

- 无效 ISBN、无查询结果、供应商错误、额度限制和相机非取消失败均进入 `paused`。
- 失败项不进入 `scanItems`。
- 页面显示失败原因和以下动作：
  - `重试扫码`：重新打开系统扫码。
  - `手工录入`：进入现有手工录入页。
  - `跳过并继续`：增加 skipped 后恢复自动循环。
  - `结束扫码`：停止循环并展示当前列表。
- 失败不得自动触发下一次付费查询。

### 6.4 结束与继续

- 页面反馈窗口中的“结束扫码”以及系统扫码取消都会调用统一的 `stopContinuousScan`。
- 停止只关闭自动循环和清理下一次扫码计时器，不清空会话。
- 停止后显示列表、书架选择和确认入馆区域。
- “开始扫码”可继续当前会话。

## 7. 待确认列表

- 列表只展示成功查询的标准图书。
- 每行展示封面、书名、作者、ISBN 和“本轮 N 册”。
- 相同 ISBN 合并展示。
- 提交前每行显示删除按钮。
- 删除直接移除整行以及该行全部本轮册数，并重新计算待入馆总册数。
- 删除需要轻量确认：`从本轮列表移除？尚未加入绘本馆。`
- 列表为空时显示“还没有待入馆的绘本”，保留“开始扫码”。
- 提交开始后禁止删除和重新扫码。

## 8. 目标书架选择

- 停止扫描且列表非空时显示“选择书架（可选）”。
- 点击后加载 `bookshelfService.listShelves` 并显示单选底部面板。
- 可以选择一个书架或选择“不加入书架”。
- 已选择时页面显示书架名称和“更换”。
- 会话缓存只保存 `bookshelf_id` 和书架名称；提交前重新验证书架仍存在。
- 未选择书架时不得调用 `addBooks`、`batchUpdate` 或其他书架写 action。

## 9. 统一入馆

### 9.1 提交入口

- 主按钮：`确认入馆（N 册）`。
- N 是全部 `scanItems.scan_count` 之和，不是不同版本数量。
- 空列表、自动扫描中或正在提交时禁用。

### 9.2 逐册写入

每一册仍使用一次独立 `libraryService.addBook` 请求：

```json
{
  "edition_id": "edition_id",
  "quantity_delta": 1,
  "scan_session_id": "scan_session_id"
}
```

调用 `services.library` 时必须显式传入该册对应的稳定 `requestId`。首次提交前为每册生成 UUID v4，先写入本地会话，再发出请求：

```text
commit_operations[]:
  request_id  该册固定使用的 UUID v4
  status      pending | processing | completed | failed
```

原因：

- 复用现有云端事务增量逻辑，避免客户端读取数量后覆盖并发修改。
- 每个写请求有独立且可恢复的 UUID 和幂等记录。
- 同一本书扫 N 册时顺序执行 N 次，成功一次立即增加 `committed_count` 并持久化。
- 客户端超时、断网或 `REQUEST_IN_PROGRESS` 时复用原 `requestId`；云端完成后返回同一结果，不会重复增加数量。
- 服务端明确返回非重试型业务错误时，该操作标记 failed。只有用户主动重试该失败项时才生成并持久化新的 `requestId`，随后重新提交。
- 异常恢复时只处理未 completed 的操作，不会重复增加已成功数量。

单个条目提交前可以查询当前馆藏数量做 99 册上限预检；云函数仍是最终校验者。超过上限时该条目保持 failed，不静默截断。

### 9.3 状态与部分失败

- 行状态依次显示“待入馆 / 入馆中 / 已入馆 / 失败”。
- 每次成功写入后立即保存本地进度。
- 收到 `REQUEST_IN_PROGRESS` 时短暂轮询同一个 `requestId`，不得换新 ID。
- 网络异常属于结果未知，保留原 `requestId`，不得直接生成新请求。
- 任意条目失败时停止该条目的剩余提交，但继续处理其他条目。
- 全部条目处理后，若存在未完成册数，留在本页面并显示“重试失败项”。
- 已成功册数不会再次提交。
- 一旦提交开始，列表不再允许删除；避免把已入馆数据误认为仍可无成本撤销。

## 10. 加入书架

- 只有全部待确认册数成功入馆后，才执行书架关系写入。
- 未选择书架：跳过本节，直接完成。
- 已选择书架：收集每个条目的唯一 `user_book_id`，每批最多 50 个调用 `bookshelfService.addBooks`。
- 已在目标书架中的书由服务端计入 `already_present_count`，不重复创建关系。
- 书架写入失败时保留会话和已完成入馆状态，重试只执行书架加入，不重复入馆。
- 全部成功后显示实际加入书架的不同绘本数。

## 11. 完成与离开

- 入馆以及可选书架操作全部成功后：
  1. 记录连续扫码完成事件。
  2. 清除当前 `scan_session_id` 本地缓存和索引键。
  3. 显示成功提示。
  4. 返回绘本馆并刷新数据。
- 用户未确认就离开：不做云端写入，保留 24 小时草稿。
- 恢复草稿时显示待确认列表、已提交进度和目标书架；不会自动开始扫码或提交。
- 草稿过期后只删除本地数据，不需要服务端补偿。

## 12. 本地缓存与计时器安全

- 保留现有 `scan_session_id` 键结构和 24 小时 TTL。
- 新缓存结构增加版本号，旧版本汇总缓存不直接恢复为新待确认列表。
- 页面 `onHide`、`onUnload`、停止扫描和提交开始时均清理自动扫描计时器。
- 异步回调在 `setData` 或重新打开扫码前检查页面是否仍存活、会话 ID 是否一致。
- `scanContinuous` 继续保留重入锁。

## 13. 页面结构与文案

连续扫码区域按阶段展示：

### Ready

- 标题：`连续录入绘本`
- 说明：`扫码成功后会自动继续，结束后统一确认入馆。`
- 主按钮：`开始扫码`
- 有草稿时在按钮上方展示待确认数量。

### 自动扫描反馈

- 成功：`扫码成功`
- 副文案：`《书名》已加入本轮列表，即将继续扫描。`
- 次按钮：`结束扫码`

### Paused

- 错误横幅和四个明确动作。

### Stopped / Review

- 顶部显示`本轮共 N 种 · M 册`。
- 待确认列表。
- `开始扫码`。
- `选择书架（可选）`。
- 固定底部主按钮`确认入馆（M 册）`。

删除以下内容：

- “继续扫码”文案。
- “结束并查看汇总”按钮。
- `mode === "summary"` 页面。
- 新增、数量增加、跳过和失败四宫格汇总。
- “再扫一轮”按钮。

## 14. 埋点

保留并调整：

- `continuous_scan_started`
- `continuous_scan_book_added`：只在一册实际入馆成功后记录 `added` 或 `duplicate`；查询成功但仅进入待确认列表时不记录此事件。
- `continuous_scan_finished`：只有统一入馆流程完成后记录。

沿用 result code：

- `skipped`
- `failure`
- `added`
- `duplicate`

其中 `skipped` 和 `failure` 仍在对应扫描结果发生时记录，用于保持现有管理指标口径；加入书架的结果使用现有 `books_added_to_shelf` 事件，不复用连续扫码入馆事件。

事件不得记录 ISBN、书名、孩子信息或错误原文。

## 15. 错误与边界

- 0 本时不能确认入馆。
- 单轮最多 100 次扫码尝试。
- 单本馆藏数量最多 99 册。
- 同一 ISBN 扫描多次只占列表一行，但按实际册数提交。
- 供应商查询成功但页面退出时只保留本地标准字段，不写馆藏。
- 目标书架在提交前被删除时提示重新选择，不影响入馆。
- 入馆成功、书架失败时允许只重试书架步骤。
- 网络中断恢复后依据 `committed_count` 继续，不重新提交已成功册数。

## 16. 测试与验收

### 16.1 扫码循环

- 点击“开始扫码”只打开一个系统扫码实例。
- 成功后 800 毫秒自动打开下一次扫码。
- 结束按钮和系统取消都停止循环并展示列表。
- 页面隐藏或卸载后不会继续调起扫码。
- 查询失败暂停，不自动消耗下一次付费查询。
- 100 次上限停止循环。

### 16.2 列表

- 成功查询不会调用 `libraryService.addBook`。
- 相同 ISBN 合并并累计册数。
- 删除后不会产生云端写请求。
- 列表和提交进度可在 24 小时内恢复。
- 空列表状态正确。

### 16.3 统一入馆

- 未选书架时只调用 `libraryService.addBook`。
- 每册独立请求并使用独立 requestId。
- 每册 requestId 在请求前持久化；模拟“云端成功但客户端丢失响应”后重试不会重复加数量。
- `REQUEST_IN_PROGRESS` 和网络异常复用原 requestId。
- 新书、多册新书、已有书数量增加均正确。
- 部分失败后重试不重复增加已成功册数。
- 99 册上限显示明确错误。

### 16.4 书架

- 书架为单选。
- 未选书架不发起任何书架写请求。
- 全部入馆完成后才调用 `addBooks`。
- 50 本以上按批处理。
- 已存在关系被安全跳过。
- 书架失败重试不重复入馆。

### 16.5 页面与视觉

- 320、375、430px 下列表、删除按钮和固定底部操作栏不溢出。
- 扫描成功、暂停、待确认、提交中、部分失败和空状态信息层级清楚。
- 删除操作使用危险色但不过度强调。
- 不再出现独立汇总页和“继续扫码”。
