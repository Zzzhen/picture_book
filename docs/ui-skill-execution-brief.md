# Frontend Design Skill 执行摘要

## 产品落点

- 主题：家庭藏书，不是儿童娱乐社区。
- 用户：需要快速盘点、寻找和整理几十至数百本绘本的家长。
- 单一任务：让用户把实体绘本可靠地收进数字馆，并愿意持续整理。

## 视觉执行

- 色彩：暖纸 `#F7F3EA`、森林绿 `#315A45`、纸面白 `#FFFEFB`、陶土 `#C96E50`、主文字 `#20251F`、次文字 `#59635B`。
- 字体：宋体只用于绘本馆名称和欢迎语；系统黑体承担正文和交互；数据使用清晰的小号系统字。
- 布局：顶部像藏书档案扉页，中部以 2/3 列封面网格为主体，工具条吸顶，空/错状态给出明确下一步。
- 记忆点：家藏书票印章只出现在建馆、馆首页和空馆，每页最多一次。
- 动效：只保留按压、状态切换、Bottom Sheet 和加书成功四类短动效。

## 防模板化复核

暖米色、宋体和陶土色容易成为 AI 设计默认组合，因此采取以下修正：

1. 不使用渐变、玻璃拟态、装饰性大数字 Hero 或无业务含义的编号。
2. 陶土色只表达藏书来源、审核印记和少量提醒，不作为大面积按钮颜色。
3. 使用书票、书脊、版本信息和馆藏数量等真实收藏语汇建立辨识度。
4. 绘本封面始终是页面主视觉，普通卡片不滥用阴影和装饰。
5. 文案使用用户能控制的动作，例如“加入绘本馆”“继续扫描”“修改后重新提交”。

## 页面验收问题

- 页面是否一眼可知当前要完成的任务？
- 空状态是否说明为什么为空，并给出下一步？
- 错误是否说明可恢复动作，而不是只写“失败”？
- 书票是否每页最多一次？
- 页面是否仍像家庭藏书工具，而不是通用后台、商城或儿童社区？
- 320、375、430 像素宽度下是否保持信息层级与点击面积？
